# Discord遠隔Codex操作システム仕様

## 要件

別PCのDiscordで指示を送り、ホスト上のCodexが反応し、進捗と応答を返す。危険な操作は実行前にDiscordで承認を得る。本システムが起動・管理するCodex会話を対象とする。

## 構成

Discord → Python Bot → stdioのCodex app-server → 作業環境。待受ポートを追加しない。Python 3.10以上、discord.py、Codex CLIを利用。モデルの既定値はgpt-6-lunaとし、利用できない場合の自動変更はしない。

## 機能

- 許可したサーバー・チャンネル・ユーザーIDが全て一致した指示のみ受け付ける。DM・Bot・Webhookは拒否する。
- 指示、状態照会、停止、新規会話、承認、拒否を提供する。同時実行は1件とする。
- 開始・進捗・完了・失敗・承認待ちを通知。長文を分割しメンションを無効化する。
- 会話識別子をローカル保存する。再起動時の操作は自動再実行しない。

## 権限・承認

フルアクセスは承認後に必要な操作を実行できる権限として扱う。通常はread-onlyとし、Codexの実行前承認をDiscordへ転送する。danger-full-access/neverは承認を保証できないため使用しない。CLI 0.156.1の実際のスキーマに合わせる。

削除、上書き、設定・権限変更、外部公開・送信、依存導入、任意スクリプト実行などの危険操作に対し、自然言語の約束や危険語判定だけに依存しない。実装上保証できないツール経路は無効化・拒否し制約を明記する。読取専用内で許されるコマンドを含め、承認範囲の実挙動を試験する。

承認を操作内容・作業ディレクトリ・要求ID・会話・ターン・操作ユーザー・チャンネルに結び付ける。1回限り、期限付き。セッション全体や永続的な許可は提供しない。期限切れ・切断・通知失敗・停止・プロセス異常時は拒否する。承認待ち中も停止できること。

## 設定・記録

認証情報は環境変数またはGit対象外.envに置く。秘密情報、認証ファイル、作業状態をコミットしない。監査ログは要求識別子と結果を中心に記録する。

## 試験運用

ユーザー指定の C:\project\ubuntu_sandbox に専用コピーを配置し、既存codex-ubuntu22-sandboxコンテナのcodexユーザーと専用venvを使用する。マウントや既存サービスの境界を広げない。環境変更時は同環境のWORKLOG.mdへ追記する。コンテナでの権限はWindowsホスト全体への権限とは異なる。

## 受入条件

許可ユーザーの指示・応答、許可外拒否、承認前未実行、単回承認、拒否・期限切れ・切断・停止時の非実行、長文・同時要求・プロセス異常を試験する。認証不要の自動試験と実Discord/Codex接続の確認結果を区別する。
